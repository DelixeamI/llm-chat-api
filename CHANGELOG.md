# Changelog

Все заметные изменения проекта документируются в этом файле.
Формат соответствует [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии следуют [Semantic Versioning](https://semver.org/lang/ru/).

## [1.0.0] — 2026-10-15

Первый стабильный релиз: полнофункциональный асинхронный отказоустойчивый шлюз к LLM с полным циклом наблюдаемости, защитой квотами, кэшированием и биллингом.

### Added
- **Отказоустойчивость и надежность (Resilience):**
  - Таймауты на вызовы LLM и настраиваемые повторные попытки с экспоненциальной паузой (exponential backoff) и случайным разбросом (jitter) при временных сбоях.
  - Ограничение числа одновременных вызовов к модели через `asyncio.Semaphore`.
  - Эндпоинты `/health` (проверка процесса) и `/ready` (проверка готовности PostgreSQL и Redis с кэшированием статуса).
  - Graceful degradation: сохранение обработки чата при временной недоступности Redis.
- **Работа с LLM и структурированный вывод:**
  - Абстракция провайдера модели (`Protocol`) для интеграции с Ollama и любыми OpenAI-совместимыми API.
  - Строгая валидация ответов по JSON Schema из моделей Pydantic v2.
  - Контур автоматического восстановления (recovery loop) с передачей модели описания ошибки валидации.
  - Контроль контекстного окна модели до отправки запроса (`reject` или `truncate_oldest`).
  - Потоковая генерация ответов через Server-Sent Events (`POST /v1/chat/stream`) с расчётом метрики Time-To-First-Token (TTFT).
- **Хранилище данных и биллинг:**
  - Асинхронное сохранение диалогов и сообщений в PostgreSQL через SQLAlchemy 2 + asyncpg.
  - Автоматические миграции базы данных через Alembic (7 версий схемы).
  - Журнал расхода токенов (`usage_logs`) по каждому вызову и расчёт точной стоимости в USD и RUB (`Decimal`) с прогнозом на месяц.
- **Слой кэширования и безопасности (Redis):**
  - Кэширование детерминированных ответов модели (`temperature=0`) с изоляцией по клиентам.
  - Ограничение частоты запросов (Rate Limiting) по скользящему окну на атомарных Lua-скриптах.
  - Поддержка заголовка `Idempotency-Key` для исключения дублирования запросов и двойных списаний.
  - Аутентификация по `X-API-Key` с разделением прав (`chat`, `admin`) и изоляцией диалогов между клиентами.
- **Наблюдаемость (Observability) и инфраструктура:**
  - Структурированное JSON-логирование со сквозным `X-Request-ID` и маскированием секретов.
  - Экспорт метрик Prometheus (`/metrics`): latency, TTFT, токены, затраты, статус-коды, попадания в кэш.
  - Распределённая трассировка OpenTelemetry (`traceparent`, спаны ожидания слотов семафора и сетевых вызовов).
  - Двухэтапный Dockerfile и `docker-compose.yml` (приложение, миграции, PostgreSQL, Redis, mock-сервер модели).
  - Автоматизированный CI-пайплайн на GitHub Actions: линтинг (Ruff), строгая типизация (mypy strict), проверка lock-файлов, интеграционные тесты с реальными PostgreSQL 17 и Redis 8, контроль покрытия тестами >= 90%.

### Fixed
- Устранена утечка пула соединений Redis при инициализации клиента (`filterwarnings=error`).
- Обеспечен детерминированный порядок сообщений в диалогах с помощью sequence-колонки `seq`.
- Корректная обработка обрыва соединения и отката транзакций при потоковых ответах SSE.
- Предотвращено отключение логгеров приложения при вызове Alembic-миграций из кода.
- Порты баз данных PostgreSQL и Redis изолированы на `127.0.0.1` в Compose-окружении.

### Known Limitations
- Инференс при локальном тестировании с Ollama ограничен последовательной обработкой (`OLLAMA_NUM_PARALLEL=1`). Для высоконагруженного использования шлюз подключается к кластеру vLLM/TGI или облачному провайдеру.
- Подробный перечень архитектурных компромиссов описан в [docs/trade-offs.md](docs/trade-offs.md).
