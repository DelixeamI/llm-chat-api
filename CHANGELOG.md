# Changelog

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/). Версии — по неделям роадмапа.

## [1.0.0] — 2026-10-15

Первый целостный выпуск: сервис, который можно запустить одной командой, проверить, наблюдать и
разобрать по документам.

### Добавлено

**Неделя 6 — наблюдаемость, контейнеры, CI**
- Структурированные JSON-логи, идентификатор запроса (`X-Request-ID`), строки запроса и вызова
  модели; защита от попадания промптов, ответов и ключей в лог.
- Метрики Prometheus: HTTP, вызовы модели (задержка, TTFT, токены, стоимость, ошибки, повторы),
  структурные отказы, кэш, лимит, аутентификация; `GET /metrics`.
- Трассировка OpenTelemetry: дерево шагов запроса, `llm.slot_wait_ms`, `traceparent`, `trace_id` в
  логах.
- `GET /ready`: PostgreSQL и Redis с пределом времени и кэшем ответа; `/health` ничего не проверяет.
- Dockerfile из двух этапов, Docker Compose с миграциями и ожиданием готовности, lock-файлы
  зависимостей, заглушка модели, дымовой тест, `scripts/make_env.py`.
- CI на GitHub Actions: Ruff, mypy, тесты на настоящих PostgreSQL и Redis с покрытием, сборка образа,
  проверка всего стека и корректной остановки.

**Неделя 5 — Redis и защита API**
- Redis: клиент с пулом, кэш ответов при `temperature 0`, приватный по клиенту.
- Потоковые ответы `POST /v1/chat/stream` (SSE) с TTFT.
- Аутентификация по `X-API-Key`, права `chat` и `admin`, владелец диалога.
- Ограничение частоты запросов: скользящее окно в Lua, `429` с `Retry-After`.
- Идемпотентность: `Idempotency-Key` для `/v1/chat` и `/v1/chat/structured`.
- Сценарии сбоев, воспроизведённые намеренно, и тесты на них.

**Неделя 4 — структурированный вывод и учёт**
- `POST /v1/chat/structured`: JSON Schema из Pydantic, валидация, восстановление.
- Журнал расхода токенов, стоимость в USD и RUB, отчёты.
- Контроль контекстного окна: `reject` и `truncate_oldest`.

**Недели 1–3 — основа**
- FastAPI, строгие схемы Pydantic v2, слоистая архитектура.
- Провайдер Ollama за `Protocol`, таймауты, повторы с jitter, семафор, общие клиенты.
- PostgreSQL, SQLAlchemy 2 (async), Alembic, транзакции, API диалогов.

### Исправлено по ходу

- Незакрытые соединения Redis при `Redis(connection_pool=…)` (найдено `filterwarnings=error`).
- Порядок сообщений по `created_at` давал обратный порядок: заменён на `seq`.
- Сбой записи после выданного текста в потоке обрывал поток молча: теперь событие `error`.
- Недоступная база давала 500 с трассировкой: теперь 503 `database_unavailable`.
- Миграции, запущенные из кода, отключали логгеры приложения (найдено в CI).
- Порты PostgreSQL и Redis были открыты на всех интерфейсах: теперь только `127.0.0.1`.
- Библиотека трассировки писала сообщение исключения в статус span-а: теперь только тип.

### Известные ограничения

Перечислены в [README](README.md#известные-ограничения): нет общего дедлайна запроса, расход
пишется в одной транзакции с сообщениями, лимиты на процесс, оценка токенов — эвристика, нет CD,
ключи в переменной окружения.
